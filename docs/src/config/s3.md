# S3 (`type: s3`)

A **sink**: it delivers the staged files a file-output destination (e.g.
[`parquet`](./parquet.md)) produced to an **S3 bucket** — AWS S3, or any
S3-compatible store (MinIO, Ceph, Cloudflare R2, …) through `endpoint`. Nothing
is needed on the host: requests are signed with AWS SigV4 in pure Rust and sent
over rustls (no AWS CLI, no SDK, no C toolchain).

- Sink binary: `loadsmith-sink-s3`

| Field | Type | Default | Description |
|---|---|---|---|
| `bucket` | string | — (required) | The bucket. |
| `region` | string | `AWS_REGION`, then `AWS_DEFAULT_REGION`, then `us-east-1` | The bucket's region (part of the signature). |
| `endpoint` | URL | `https://s3.<region>.amazonaws.com` | An S3-compatible endpoint, e.g. `http://minio:9000`. |
| `url_style` | `virtual-host` / `path` | `virtual-host` on AWS, `path` with an `endpoint` | How the bucket is addressed (`https://<bucket>.<host>/…` or `https://<host>/<bucket>/…`). |
| `prefix` | string | — | Prepended to every key: `raw/orders` → `raw/orders/<key>`. |
| `key` | template | `{run_date}/{run_id}/{file}` | The object key under `prefix`. Placeholders: `{file}` (required — the staged file's name), `{run_id}`, `{run_date}` (`YYYY-MM-DD`, UTC), `{run_time}` (`YYYYMMDDTHHMMSSZ`, UTC), `{pipeline}`. An unknown placeholder is an error. |
| `access_key_id` / `secret_access_key` | string | `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` | Static credentials; both or neither. Pass them with `{{ secret(...) }}` or `{{ env(...) }}`, or leave them out to read the standard variables. |
| `session_token` | string | `AWS_SESSION_TOKEN` | For temporary credentials (STS). |
| `part_size_mib` | integer ≥ 5 | `16` | A file up to this size goes in one `PUT`; a larger one as a multipart upload in parts of this size (raised as needed to stay within S3's 10,000 parts). One part is held in memory at a time. |
| `request_timeout_seconds` | integer | `300` | Limit for one HTTP request. |
| `max_attempts` | integer ≥ 1 | `4` | Tries per request on network errors, `429` and `5xx` (backoff 1s, 2s, 4s, …). Other errors (`403 AccessDenied`, `404 NoSuchBucket`, …) fail at once. |

Unknown keys are rejected (or only warned about with `--ignore-unknown-keys`).

```yaml
destination:
  type: parquet
  config:
    prefix: orders          # no `path`: the core stages the files
    compression: zstd
    max_file_size: "128MiB"

sink:
  type: s3
  config:
    bucket: acme-data-lake
    region: sa-east-1
    prefix: raw/erp/orders
    # key: "{run_date}/{run_id}/{file}"   (the default)
    access_key_id: "{{ secret('vault', 'aws#access_key_id') }}"
    secret_access_key: "{{ secret('vault', 'aws#secret_access_key') }}"
```

A run started on 2026-10-22 delivers `s3://acme-data-lake/raw/erp/orders/2026-10-22/<run id>/orders.00000001.zstd.parquet`, …

## Delivery

- **Every run adds its own objects.** The default key names the run (its date
  and id, from the core's `configure.run`), so an incremental pipeline's runs
  accumulate side by side instead of overwriting each other. A `key` without
  `{run_id}` (e.g. `{file}`) makes each run replace the previous run's objects
  of the same name — choose it only for a full reload that should overwrite.
  A key naming the run needs a Loadsmith engine that sends `configure.run`
  (1.0.0-rc.2 and later); an older engine fails at `configure`, naming it.
- **Atomic per object.** S3 shows an object only once it is complete (a
  `PUT`, or a multipart upload's completion): a reader sees the whole file or
  nothing.
- **Idempotent within a run.** The key is the same across the sink's
  respawns, so a re-delivery after a crash replaces the same object. The core's
  sink supervisor tracks delivery and resumes it, so each object is delivered at
  least once.
- **Across runs, at least once.** A run that fails after delivering some
  objects leaves them in place; with `state:`, the next run re-reads from the
  last committed watermark and delivers those rows again under its own run
  prefix. Readers that must see each row exactly once should read only the
  prefixes of successful runs (the run summary's `run_id`).
- **Failed multipart uploads are aborted.** If a part or the completion fails,
  the sink aborts the upload, so its parts don't linger. A process killed
  mid-upload can't abort: an
  [`AbortIncompleteMultipartUpload`](https://docs.aws.amazon.com/AmazonS3/latest/userguide/mpu-abort-incomplete-mpu-lifecycle-config.html)
  lifecycle rule on the bucket cleans those up.

## Credentials

Static keys only, for now: in the config, or the standard `AWS_ACCESS_KEY_ID`
/ `AWS_SECRET_ACCESS_KEY` / `AWS_SESSION_TOKEN` variables (which plugins inherit
from the engine). Instance and task roles (EC2 instance profiles, ECS task
roles, EKS IRSA) are not read yet — export the role's temporary credentials into
those variables before the run.

The IAM policy needs `s3:PutObject` and `s3:AbortMultipartUpload` on the
`prefix`.
